# 02: Trace a MEPA program without jumps or calls

Status: resolved
Blocked by: 01

**What to build:** the first tracer bullet through the machine trace. An artifact agent writes an ordinary Stage with `input`, a MEPA listing in a `start=0` fence, a registers table and a memory table, and a build of a few lines, `trace(mepa, notes)`, importing only the design system. The page steps through the run: the line that ran reversed, the next one dashed, every changed cell strong, each step said in the artifact's language. This slice gives the general layer (the run loop, automatic `strong`, number formatting) and MEPA's instructions for a program with no labels, jumps or subroutines. Labels and jumps come in 05 and subroutines in 06, and failures for programs and notes that don't fit in 04. The bound is [Machine trace](../spec.md) › Behaviour, The general layer, Narration, Notes and MEPA.

- [x] `trace(machine, notes)` is exported beside `defineBuild` and returns a `Build`. A machine definition gives `parse`, `start`, `step` and `view` as the spec says. `view` returns a `Step` without `say`.
- [x] MEPA is a machine module under `@artifactory/design-system/machines/`. The check's `build-import` rule lets a build import `stage-build` and the machine modules, and still refuses anything else, its message naming both. Machine and trace code type-checks under the builds' own settings (ES library only, strictest), since builds import it.
- [x] `build-input` still applies: a build written like the spec's example (`reads` naming exactly the Stage's fields, no type argument) passes, and one whose fields don't match fails as today.
- [x] The run loop: a first step shows the starting state, then one step per machine step until it halts. A run past 200 steps gets the Stage's existing refusal on the page ("Isso dá mais de 200 passos…") and `returns more than 200 steps` in the check.
- [x] A machine fault refuses the run: division by zero, a read with no input left, the stack dropping below its bottom, and any other such fault the definition has. The refusal names the instruction's shown line number and the fault, in pt-BR and English, and the page keeps working. A fault never escapes as a throw from design-system code; 04 gives its `stage-run` failure line in the check.
- [x] Automatic `strong`: every cell whose text changed since the step before is `strong`. The first step marks only what the view marks, and a view can still mark a cell `strong` itself (a write of the value the cell already held).
- [x] Number formatting, shared so every machine says numbers alike: a true minus sign shown (`−1`), the spoken form said ("menos 1"), and `?` shown with "sem valor" said for a cell with no value (English equivalents in English).
- [x] Narration in pt-BR and English, chosen by the artifact's main language, which reaches the build with its content (01), on the page and in the check alike. Every sentence says operators in words ("M[4] recebe 7", never "M[4] ← 7").
- [x] MEPA covers `INPP`, `AMEM`, `DMEM`, `LEIT`, `ARMZ`, `CRVL`, `CRCT`, `SOMA`, `MULT`, `DIVI`, `IMPR`, `PARA`, and `FIM` as the listing's last line. Each listing line is an instruction with its arguments and an optional `;` comment, address k being shown line k.
- [x] The registers table (`Registrador | Valor`, or `Register | Value`) has the rows `i`, `s`, every `D[k]` the program uses, and `entrada` / `saída` (`input` / `output`), which list values in order, `—` when empty.
- [x] The memory table (`Célula | Dado | Papel | Desl. | Topo`, or `Cell | Data | Role | Offset | Top`) has rows `M[0]` up to as many as the artifact writes, in any order, and the view reads how many from the table. `Papel` is optional and written only when the table has it. A cell above `s` is `muted` with no role; `← s` marks the top.
- [x] Lines: the instruction that ran is `reversed`, the one `i` points at next is `dashed`, unless the run has stopped.
- [x] Notes: `reads` (field names in the order `LEIT` reads them), `roles` by address (an `AMEM n` takes a list of `n`), and `after` by address. Notes never come from `;` comments.
- [x] Tests at the check's seam (fixture repos): a fixture artifact whose straight-line MEPA trace passes, and a variant whose memory table as written differs from the first example's result fails with the existing "the last step leaves …" line, its expected value worked out by hand from the program. A non-machine build is unaffected.
- [x] Docs in the same commit: doc comments on `trace` (its notes, the general layer, the 200-step limit) and on the MEPA module (its instructions so far, its two tables as written in both languages, its notes), the Stage's build section of `COMPONENTS.md` regenerated with `pnpm components`; the `artifact` skill's `stage.md` covers `trace` and the widened import rule; `rules.md` › Custom builds says "propose a component or a machine" and that a build running a machine the design system has uses `trace`, never a copy; `PRODUCT.md` gains the line that machines are the exception to "work across subjects" (ADR 0008).
- [x] Shared parts: no visual part changes; the build module's types reach every build, and the catalog's and the sample's builds still type-check. Design-system work, so a local session.

## Comments

### 2026-11-09: what 01 hands a build

From machine trace 01's implementation: `steps(input, content)` gets `Content` from `stage-build.ts`: `content.code[0]` is the fence's lines as `{ line, text }` in order, `line` the shown number (0 first under `start=0`, so a listing whose first `line` isn't 0 is the "fence doesn't start at 0" failure) and `text` the raw line, with leading spaces and any `;` comment. `content.tables` holds `{ columns, rows }` as written, so the memory table's rows tell the view how many cells there are. `content.lang` is `"pt-BR"` or `"en"`. Each run gets a fresh copy, so `trace` may keep or change what it's given. On both sides the language comes from `mainLanguage` in `step-applier.ts` (the nearest `[lang]`). `runBuild` now takes it as a fourth argument, and the check passes it in its worker `Job`. Fixture tests for a build that reads content live in `tests/check/artifact-checks.test.ts` (the `conteudo` Stage in `customBuilds`).

### 2026-11-09: resolved

**Result:** `trace(machine, notes)` in `@artifactory/design-system/stage-build` returns a `Build` typed by its `reads` (`Build<Record<Reads, number>>`). It parses the program from the content, starts the machine on the fields' values in `reads` order, and steps it until it halts. The first step shows the starting state ("A máquina ainda não deu nenhum passo." / "The machine hasn't taken a step yet."), and the steps stop one past the 200-step limit, so a longer run gets the Stage's existing refusal. Every cell whose text changed since the step before is `strong`, unless the view marked it itself. A machine fault refuses the run: on the page "Linha 8: divisão por zero. Tente outros números." (English "Line 8: division by zero. Try other numbers."; with `choose`, "Escolha outra opção."), and in the check "with `x = 7, y = 0`, the machine faults at line 8: division by zero". MEPA (`@artifactory/design-system/machines/mepa`, `design-system/src/machines/mepa.ts`) covers the listed instructions, both tables in both languages, the lines, `roles` and `after`. The general layer's types and number formatting (`shownNumber`: `−1`, `?`; `spokenNumber`: "menos 1", "sem valor" / "minus 1", "no value") are in `design-system/src/machine.ts`, which isn't a package export. `build-import` lets a build import `stage-build` and the package's `./machines/*` exports and still refuses anything else, its message naming both.

**Decisions:**
- `reads` belongs to the general layer, not MEPA's notes. `trace` types the build's input from it, so `build-input` keeps checking a trace against the Stage's fields with no type argument, and `start` gets the values in `reads` order.
- A fault travels as data from `step` (`{ fault: { line, fault: { "pt-BR", en } } }`). `trace` throws it as `MachineFault`, the only way out of `steps`, and `runBuild` catches it into a `{ refused: "fault" }` run, so it never reaches the check as "`steps` throws". It's said in both languages because the check reports in English and the page in the artifact's language. The check's line for it is already here, tested with division by zero; 04 owns the other fault kinds' tests and may reword it.
- Parse problems are returned as data, but `trace` still throws them as one plain `Error` until 04 gives them a refusal (noted on 04).
- `PARA` leaves `i` on its own line, and the run has stopped, so no line is dashed.
- `entrada` / `input` lists the values not read yet.
- Roles: an `AMEM n` note is a list; any other note is one role, for the cell its instruction writes. `ARMZ` keeps a cell's role unless the note gives one. Any other write without a note clears it.
- Faults MEPA defines besides the three named: `s` with no value before `INPP`, a cell or `D[k]` with no value, an address below 0, and reaching `FIM`.
- `Desl.` (`Offset`) is left as written until 06 adds records, and MEPA's doc comment says so.
- `strong` from the diff never overrides a mark the view gave, so the cells above `s` stay `muted` when their role clears.
- The first step's sentence is the general layer's, not MEPA's, since every machine has a starting state.
- `build-input`'s hint for a trace names `reads` instead of `defineBuild<…>`, found through the callee's resolved symbol. The failure itself is as before.
