# 02: Trace a MEPA program without jumps or calls

Status: ready-for-agent
Blocked by: 01

**What to build:** the first tracer bullet through the machine trace. An artifact agent writes an ordinary Stage with `input`, a MEPA listing in a `start=0` fence, a registers table and a memory table, and a build of a few lines, `trace(mepa, notes)`, importing only the design system. The page steps through the run: the line that ran reversed, the next one dashed, every changed cell strong, each step said in the artifact's language. This slice gives the general layer (the run loop, automatic `strong`, number formatting) and MEPA's instructions for a program with no labels, jumps or subroutines. Labels and jumps come in 05 and subroutines in 06, and failures for programs and notes that don't fit in 04. The bound is [Machine trace](../spec.md) › Behaviour, The general layer, Narration, Notes and MEPA.

- [ ] `trace(machine, notes)` is exported beside `defineBuild` and returns a `Build`. A machine definition gives `parse`, `start`, `step` and `view` as the spec says. `view` returns a `Step` without `say`.
- [ ] MEPA is a machine module under `@artifactory/design-system/machines/`. The check's `build-import` rule lets a build import `stage-build` and the machine modules, and still refuses anything else, its message naming both. Machine and trace code type-checks under the builds' own settings (ES library only, strictest), since builds import it.
- [ ] `build-input` still applies: a build written like the spec's example (`reads` naming exactly the Stage's fields, no type argument) passes, and one whose fields don't match fails as today.
- [ ] The run loop: a first step shows the starting state, then one step per machine step until it halts. A run past 200 steps gets the Stage's existing refusal on the page ("Isso dá mais de 200 passos…") and `returns more than 200 steps` in the check.
- [ ] A machine fault refuses the run: division by zero, a read with no input left, the stack dropping below its bottom, and any other such fault the definition has. The refusal names the instruction's shown line number and the fault, in pt-BR and English, and the page keeps working. A fault never escapes as a throw from design-system code; 04 gives its `stage-run` failure line in the check.
- [ ] Automatic `strong`: every cell whose text changed since the step before is `strong`. The first step marks only what the view marks, and a view can still mark a cell `strong` itself (a write of the value the cell already held).
- [ ] Number formatting, shared so every machine says numbers alike: a true minus sign shown (`−1`), the spoken form said ("menos 1"), and `?` shown with "sem valor" said for a cell with no value (English equivalents in English).
- [ ] Narration in pt-BR and English, chosen by the artifact's main language, which reaches the build with its content (01), on the page and in the check alike. Every sentence says operators in words ("M[4] recebe 7", never "M[4] ← 7").
- [ ] MEPA covers `INPP`, `AMEM`, `DMEM`, `LEIT`, `ARMZ`, `CRVL`, `CRCT`, `SOMA`, `MULT`, `DIVI`, `IMPR`, `PARA`, and `FIM` as the listing's last line. Each listing line is an instruction with its arguments and an optional `;` comment, address k being shown line k.
- [ ] The registers table (`Registrador | Valor`, or `Register | Value`) has the rows `i`, `s`, every `D[k]` the program uses, and `entrada` / `saída` (`input` / `output`), which list values in order, `—` when empty.
- [ ] The memory table (`Célula | Dado | Papel | Desl. | Topo`, or `Cell | Data | Role | Offset | Top`) has rows `M[0]` up to as many as the artifact writes, in any order, and the view reads how many from the table. `Papel` is optional and written only when the table has it. A cell above `s` is `muted` with no role; `← s` marks the top.
- [ ] Lines: the instruction that ran is `reversed`, the one `i` points at next is `dashed`, unless the run has stopped.
- [ ] Notes: `reads` (field names in the order `LEIT` reads them), `roles` by address (an `AMEM n` takes a list of `n`), and `after` by address. Notes never come from `;` comments.
- [ ] Tests at the check's seam (fixture repos): a fixture artifact whose straight-line MEPA trace passes, and a variant whose memory table as written differs from the first example's result fails with the existing "the last step leaves …" line, its expected value worked out by hand from the program. A non-machine build is unaffected.
- [ ] Docs in the same commit: doc comments on `trace` (its notes, the general layer, the 200-step limit) and on the MEPA module (its instructions so far, its two tables as written in both languages, its notes), the Stage's build section of `COMPONENTS.md` regenerated with `pnpm components`; the `artifact` skill's `stage.md` covers `trace` and the widened import rule; `rules.md` › Custom builds says "propose a component or a machine" and that a build running a machine the design system has uses `trace`, never a copy; `PRODUCT.md` gains the line that machines are the exception to "work across subjects" (ADR 0008).
- [ ] Shared parts: no visual part changes; the build module's types reach every build, and the catalog's and the sample's builds still type-check. Design-system work, so a local session.
